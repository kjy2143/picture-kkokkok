# 그림콕콕 게임 제작

제작 전에 프로젝트 루트의 `docs/GAME-GENERATION-GUIDE.md`, `docs/CONTENT.md`, `docs/PRD.md`를 읽는다. 차이 구성·난이도·이미지 검수·정답 영역의 품질 기준은 생성 가이드를 따른다.
기본 입력은 주제·난이도·생성 개수다. 장면 설명은 선택 사항이며 생략하면 서로 다른 장면을 구성한다.
주제는 동물·우주·공주·동화·교통·일상, 난이도는 easy(7개)·medium(8개)·hard(10개)다.
예: `$generate-game 동물 보통 3개`, `$generate-game 6개 주제 각 난이도 1개씩`.

## 도구와 공개 경계

- Codex 내장 `image_gen`을 사용한다. 구독 한도나 도구 오류를 이유로 별도 과금 API·CLI로 바꾸지 않는다.
- 원본과 변경 그림을 코드로 그리거나 색을 바꾸는 방법으로 대체하지 않는다. 편집도 이미지 생성 도구에서 수행한다.
- 로컬 이미지는 편집 전에 `view_image`로 확인하고 편집 대상 경로를 참조한다.
- 생성 결과가 Codex 기본 저장소에 저장되면 프로젝트의 해당 제작 폴더로 복사한다. 실제 파일 경로는 도구 반환값에서 확인한다.
- 성공한 결과를 보존한다. 기존 파일을 재생성할 때는 새 시도 폴더를 사용하고 비교 후 교체한다.
- 별도 부모 검수 승인 절차 없이 등록된 게임을 빌드에 포함한다. 그림 품질·정답 영역 확인과 데이터 검사는 유지한다.
- 이 스킬은 공개 배포를 수행하지 않는다.

## 단일 게임

1. 고유 게임 ID를 정한다. `npm run content -- init <id> <주제> <easy|medium|hard> <제목>`으로 `work/content/<id>`를 준비한다.
2. 장면과 비율·해상도를 계획한다. 선명한 윤곽과 또렷한 색의 동화책 일러스트, 텍스트·로고 없음. iPad 가로 좌우 비교에는 4:5 세로를 권장하되 사용자 지정 비율과 기존 게임의 수정 범위를 우선한다. 쉬움은 식별하기 쉬운 차이, 어려움은 풍부한 세부 묘사로 조정하며 판정 영역을 좁혀 난이도를 높이지 않는다.
3. 이미지 도구로 원본을 생성해 `original.png`로 보존한다.
4. 원본을 실제로 보고 정확히 7·8·10개의 차이를 계획한다. 색깔·표정·개수·모양·무늬·유무 중 기본 4개 이상의 유형을 섞는다. `plan.json`에 각 차이의 유형, 원본·변경 상태, 위치, 유지할 요소와 유형 배분을 기록한다. 서로 겹치지 않고 양쪽 그림에서 판정할 수 있어야 한다. 구체적인 배분과 예외는 생성 가이드를 따른다.
5. 원본을 참조해 계획한 차이만 편집한다. 나머지 배치·표정·윤곽·크기·색·프레이밍을 유지하도록 요청하고 `modified.png`로 보존한다.
6. 생성 가이드의 이미지 검수·재작업 기준에 따라 양쪽 이미지를 기본 크기와 확대로 실제 확인한다. 계획과 다른 차이나 위치 오차는 수정·재생성한다. 의도 밖 차이를 임의로 정답에 추가해 개수를 맞추지 않는다.
7. 실제 이미지의 좌표로 `puzzle.json`을 완성한다. `metadata.json`과 썸네일을 준비한다. 포맷 변환·썸네일 리사이즈는 `sharp` 등으로 수행할 수 있으나 원본·변경 그림의 의미를 바꾸지 않는다.
8. `npm run content -- stage <id>`로 완성 파일을 등록하고 `npm run content -- review-image <id>`로 검수용 이미지를 만든다.
9. `npm run dev`에서 부모가 실제 게임의 양쪽 판정·힌트·확대를 확인하도록 결과 경로를 제시한다. 제작자가 확인한 내용과 미확인 사항을 보고한다. 부모 승인 대기나 승인 명령은 요구하지 않는다.

이미지 도구가 실패하면 동일 항목을 최대 한 번 다시 시도한다. 계속 실패하면 오류와 해당 항목을 기록하고 다른 항목을 진행한다. 이미지 품질은 사람의 검수로 판단하며 도구가 정확한 차이를 보장한다고 보고하지 않는다.

## 일괄 생성과 재개

`npm run batch -- all all 1`로 초기 18개 계획을 만든다. 특정 주제 예시는 `npm run batch -- 동물 easy 3`이다.
각 항목에 서로 다른 장면을 기록하고 위 단일 흐름을 적용한다.
계획의 pending·failed 항목만 처리하고 generated·reviewed 항목은 다시 생성하지 않는다.
결과마다 `npm run content -- batch-status <계획 파일> <id> <generated|failed> <설명>`으로 상태를 기록한다.
검수 문제로 재생성할 항목은 부모가 지정한 항목만 다시 처리한다. 기존 성공 결과와 제작 이력을 보존한다.
완료 보고에는 성공·실패 목록, 검수용 이미지 경로, 다음 로컬 검수 명령을 포함한다.
