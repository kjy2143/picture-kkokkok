# 숨은그림찾기 추가 — 검토용 설계

- 작성일: 2026-10-29
- 상태: 2026-10-29 사용자 시안 승인. 앱 구현과 숨은그림 30개 제작 진행.
- 대상: 7살 주아, iPad A16, 손가락과 Apple Pencil. 가로 중심·세로 지원.
- 산출물: 놀이 선택·숨은그림 목록·숨은그림 플레이의 화면 시안 3장. 화면 속 게임 그림은 배치 예시이며 정답 좌표·제작 품질을 검증한 게임 콘텐츠가 아니다.

## 사용자 요청과 위임

사용자는 기존 틀린그림찾기에 숨은그림찾기를 추가하고, 놀이를 먼저 선택한 뒤 해당 목록을 보는 흐름을 요청했다. 첨부 HEIC 사진 4장을 검토했다. 2026-10-29 사용자는 추천 방안으로 진행하도록 위임했다. 앱 코드 구현 전에 시안을 검토한다는 조건은 유지한다.

## 선택한 방향과 대안

추천안은 별도 놀이 선택 화면 → 놀이별 목록 → 플레이의 3단계다. 읽기 전에도 그림으로 두 놀이를 구분한다. 목록마다 같은 카드·주제·난이도·진행 상태 체계를 사용한다. 진입 때 한 번 더 선택하지만, 주아가 지금 하는 놀이와 돌아갈 곳이 분명하다.

같은 목록 위의 탭으로 놀이를 바꾸는 방법은 이동이 빠르다. 다만 별도 선택 화면을 원하는 요청과 맞지 않는다. 두 놀이의 콘텐츠를 한 목록에 섞는 방법은 탐색 화면이 하나지만, 놀이 규칙을 썸네일마다 다시 구분해야 한다. 두 대안은 채택하지 않는다. 사용자의 추천안 위임에 따라 담당 에이전트가 선택했다.

## 놀이 방식

사진처럼 사물의 윤곽·무늬에 다른 물건의 모양을 숨긴다. 배경에 독립된 작은 물건을 놓는 방식만으로 구성하지 않는다. 사용자의 후속 요청으로 첫 제작 범위를 30개로 확정했다. 6개 주제에 5개씩 배분하고 쉬움 7개·보통 8개·어려움 10개의 목표를 가진 게임을 각각 10개 제작한다. 주아의 체감 난이도는 실제 플레이로 확인할 사항이다.

찾을 물건은 그림과 짧은 이름으로 보여준다. 물건 목록을 먼저 누르지 않아도 장면의 정답을 바로 고를 수 있다. 찾으면 본그림에 주황색 표시를 남기고 물건 목록에 초록색 체크와 ‘찾았어요’를 표시한다. 찾은 항목도 원래 위치에 유지한다. 이미 찾은 정답을 다시 눌러도 개수가 늘지 않는다.

시간 제한과 감점은 없다. 정답·오답·완료 효과음, 무제한 힌트, 진행 저장, 이어 풀기, 다시 풀기, 완료 후 명시적인 다음 행동은 기존 경험을 잇는다. 힌트는 미발견 물건 하나의 주변을 잠깐 보여준다. 화면 밖이면 해당 주변으로 이동한다. 자동 정답 처리는 하지 않는다.

## 화면 시안

### 놀이 선택

기존 브랜드 헤더와 소리·설정을 사용한다. ‘오늘은 어떤 놀이를 할까?’ 아래 같은 크기의 두 선택 영역을 둔다. 틀린그림찾기는 비교 그림 두 장으로, 숨은그림찾기는 한 장과 물건 예시로 표현한다. 각 영역 전체를 누를 수 있다. 게임 개수·난이도·주제 필터는 이 화면에 두지 않는다.

### 숨은그림 목록

‘놀이 선택’으로 돌아가는 행동과 현재 놀이 이름을 표시한다. 기존의 큰 썸네일·필터·진행 상태를 잇는다. 실제 목록에는 완성·검수한 30개 게임을 표시한다. 준비 중 카드나 가짜 보유 개수를 넣지 않는다. 콘텐츠가 늘어도 같은 구조로 확장한다.

한 장뿐인 초기 목록은 가로로 넓은 카드 한 개를 사용한다. 왼쪽은 장면 미리보기, 오른쪽은 제목·난이도·목표 물건 예시·진행 상태·시작 행동을 둔다. 작은 화면에서는 위아래로 배치한다. 30개 제작 요청을 반영한 실제 목록은 기존과 같은 격자로 확장하고 숨은그림의 가로 비율을 보존한다. 시안의 ‘2 / 7’과 ‘오프라인 가능’은 예시 상태이며 실제 저장을 수행한 결과가 아니다.

### 숨은그림 플레이

가로는 상단의 낮은 도구 행, 왼쪽의 큰 장면 한 장, 오른쪽의 고정 물건 목록으로 구성한다. 본그림의 제안 비율은 4:3이며 자르지 않고 전체를 보여준다. 기존 틀린그림찾기 4:5 그림·비교 배치는 유지한다. 물건 목록에는 7개가 스크롤 없이 보이게 한다. 그림과 목록은 별도로 움직여 확대해도 목표를 계속 볼 수 있다.

상단은 ‘다른 그림’, 제목, ‘2 / 7 찾았어요’, 힌트, 다시 풀기, 소리·도움말을 제공한다. iPad 가로의 도구 행은 기존 64px 수준을 목표로 하되 실제 측정으로 검증한다. 세로는 본그림 아래 물건 목록을 줄바꿈해 배치한다. 시안은 iPad 가로 기준이다. 세로·작은 휴대폰의 실측은 구현 시 수행한다.

완료하면 ‘모두 찾았어요!’와 ‘다른 그림 고르기’·‘다시 풀기’를 제공한다. 다른 그림으로 자동 이동하지 않는다.

## 기존 기능과 연결

게임 상세의 돌아가기는 해당 놀이 목록으로 이동한다. 목록의 돌아가기는 놀이 선택으로 이동한다. 브라우저 뒤로가기·앞으로가기·새로고침도 같은 경로를 유지해야 한다. 기존 ?game=<id> 직접 링크는 계속 틀린그림찾기로 열린다. 정확한 새 주소 형식은 구현 판단으로 남긴다.

기존 게임과 진행 기록은 유지한다. 새 게임 ID는 기존과 충돌하지 않는다. 소리 설정은 두 놀이가 공유한다. 정답·이미지 변경 시 해당 게임만 진행 기록을 초기화하는 기존 규칙을 유지한다. 오프라인은 열어본 게임의 장면·물건 그림·정답 파일이 모두 저장됐을 때만 가능으로 표시한다. 전체 진행 기록 초기화는 확인 문구에서 두 놀이의 기록이 포함됨을 알린다. 공개 배포는 별도 요청이 있어야 한다.

현재 Puzzle 타입과 콘텐츠 검사·내보내기는 그림 쌍을 전제로 한다. 구현 시 게임 종류를 구분하는 데이터 계약과 단일 그림용 판정·캐시·검사 경로가 필요하다. 기존 틀린그림찾기 데이터를 일괄 변환하는 범위로 넓히지 않는다.

## 콘텐츠 품질과 검증

시안의 생성 그림을 그대로 등록하지 않는다. 실제 게임을 만들 때는 7개의 숨길 대상과 위치·변형 허용 범위를 먼저 계획한다. 원본과 작은 목표 그림의 윤곽이 대응하는지 확인한다. 색과 크기 차이만으로 찾을 수 있는 쉬운 대상도 섞고, 과도한 회전·가림·작은 크기로 난이도를 올리지 않는다.

실제 정답 영역은 최종 그림을 보고 확정한다. 목표 그림은 장면 속 실제 모양을 추출하거나 정확히 대응하게 제작한다. 손가락으로 선택할 수 있는 판정 여유를 확보하되 인접 정답을 오인하지 않게 한다. 전체 그림·목표 그림·정답 영역을 따로 검수한다. 자동 검사는 파일·좌표·판정·중복 처리·진행 저장을 확인하며, 주아의 체감 난이도 확인을 대신하지 않는다.
