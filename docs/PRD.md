## 1. 문서의 구분

**2~8절은 인터뷰에서 확정한 요구사항이다.** 제품 범위와 공개 판단의 기준으로 사용한다.
**9절은 구현 권장안이다.** 구현 시 검증하고 조정할 수 있으며 확정 요구사항을 바꾸는 근거로 사용하지 않는다.
10절은 구현·검증 과정에서 확인할 사항이다. 추가 제품 요구사항 인터뷰는 필요하지 않다.

## 2. 제품 목표와 사용자 — 확정

서비스명은 **그림콕콕**이다. 7살 주아를 위한 틀린그림찾기 PWA 웹앱을 만든다.
주아는 틀린그림찾기에 익숙하며 차이 7~10개를 찾는 게임도 플레이한다.
시간이나 오답에 대한 부담 없이 끝까지 찾는 경험을 제공한다.

처음에는 부모가 게임을 골라주고 주아가 직접 푼다.
익숙해진 뒤에는 주아가 게임 선택부터 풀이까지 혼자 할 수 있어야 한다.
서비스는 가족 전용으로 제공한다. 주소를 아는 것만으로 앱과 게임 파일에 접근할 수 없어야 한다. (2026-10-29 사용자 선택)
배포 환경은 Cloudflare Workers Static Assets를 유지한다. 접근 인증은 Cloudflare Access에서 부모 이메일 허용 목록과 이메일 일회용 코드를 사용하는 방식으로 준비한다.
부모가 기기를 인증하고 아이는 별도 계정 없이 플레이한다. 부모 이메일 1개와 1주 세션의 Access 정책을 등록했다. 아직 앱을 배포하지 않았으며 실제 로그인·기기 동작은 검증하지 않았다.
개선 방향은 별도 사용 통계 대신 주아가 플레이하는 모습을 직접 관찰해 정한다.

## 3. 게임 경험 — 확정

### 3.1 홈과 게임 선택

- 큰 썸네일 카드로 게임을 표시한다.
- 카드에 주제, 난이도, 진행 상태를 표시한다.
- 주제와 난이도로 게임을 필터링할 수 있다.
- 진행 상태는 `새 게임`, `푸는 중`, `완료`로 구분한다.
- 필요한 파일이 모두 기기에 저장된 게임의 카드에 `오프라인 가능`을 표시한다.

### 3.2 그림 비교와 조작

- 가로 화면에서는 두 그림을 좌우로, 세로 화면에서는 위아래로 배치한다.
- 어느 쪽 그림에서도 차이가 있는 부분을 눌러 정답을 선택할 수 있다.
- 키보드로 그림에 초점을 옮기고 방향키로 위치를 이동해 Enter·Space로 선택할 수 있다. Shift는 미세 이동, 더하기·빼기는 양쪽 확대·축소에 사용한다.
- 첫 게임 진입에는 그림을 가리지 않는 짧은 조작 안내를 보여준다. 닫은 안내는 자동으로 다시 표시하지 않으며 도움말 버튼으로 다시 열 수 있다.
- 정답을 맞히면 두 그림의 해당 위치에 동그라미를 표시한다.
- 두 그림은 같은 위치와 배율로 함께 확대·이동한다.
- 상세 페이지의 별도 `확대 초기화` 버튼은 제공하지 않는다. (2026-10-28 사용자 요청)
- 게임 진입 시 `?game=<id>` 주소와 history 항목을 추가한다. 뒤로가기·앞으로가기·새로고침 시 주소에 맞는 게임이나 목록을 표시한다.
- 시간 제한과 오답 감점을 적용하지 않는다.
- 오답을 누르면 누른 위치에 작은 표시를 잠깐 보여준 뒤 없앤다. 정답과 구분되는 짧고 부드러운 오답 효과음을 재생한다. (2026-10-14 사용자 요청으로 변경)

### 3.3 힌트

- 아직 찾지 못한 차이 하나의 주변 영역을 양쪽 그림에서 잠깐 강조한다.
- 사용 횟수는 제한하지 않는다.
- 힌트 사용으로 정답 처리하지 않는다. 주아가 직접 정답을 눌러야 한다.

### 3.4 완료와 재플레이

- 모든 차이를 찾으면 짧은 축하 애니메이션과 `모두 찾았어요!`를 표시한다.
- `다른 게임 고르기`와 `다시 풀기` 버튼을 제공한다.
- 완료 창의 `그림 더 보기` 또는 Escape로 창을 닫고 찾은 정답을 유지한 채 그림을 볼 수 있다. 이때도 상단의 `다시 풀기`를 사용할 수 있고 재시작 전 확인한다.
- 다음 게임으로 자동 이동하지 않는다.
- 완료한 게임은 처음부터 다시 풀 수 있다.
- 게임 중에도 상단의 `다시 풀기`로 처음부터 시작할 수 있다. 찾은 정답이 있으면 확인창을 제공한다.
- 다시 시작하면 해당 게임의 정답·힌트·확대·이동을 초기화하고 기록을 저장한다. 다른 게임의 기록은 유지한다.

### 3.5 효과음과 설정

- 정답·오답·완료에 서로 구분되는 짧은 효과음을 재생한다.
- 소리는 처음 실행 시 기본으로 켜진다. 사용자가 끈 설정은 이후 실행에서도 유지한다. (2026-10-14 사용자 요청)
- 소리 켜기·끄기 설정을 기기에 저장한다.
- 배경음악은 첫 버전에서 제외한다.
- 설정에 `오프라인 게임 파일 삭제`를 제공한다. 삭제해도 진행 기록과 소리 설정은 유지한다.
- 삭제한 게임은 인터넷에 연결해 다시 열면 오프라인용으로 다시 저장한다.
- `전체 진행 기록 초기화`를 별도 항목으로 제공한다. 사용자 확인 후 실행한다.
- 설정 작업의 진행·성공·실패는 설정 창의 해당 항목 안에 표시한다. 작업 중에는 중복 실행을 막고 완료 후 다시 시도할 수 있다.

## 4. 진행 기록·오프라인·업데이트 — 확정

### 4.1 진행 기록

찾은 정답을 기기에 자동 저장한다.
앱을 닫았다가 다시 열어도 진행 중인 게임을 이어서 풀 수 있다.

| 콘텐츠 변경                   | 진행 기록 처리                     |
| ----------------------------- | ---------------------------------- |
| 변경 없음                     | 유지                               |
| 제목·썸네일만 변경            | 유지                               |
| 게임 그림 또는 정답 위치 변경 | 해당 게임만 처음부터 풀도록 초기화 |

공개 후 이전 정상 버전으로 복구할 때도 이 기준을 적용한다.
진행 기록을 일괄 삭제하지 않는다.

### 4.2 오프라인 사용

- 한 번 열어본 게임만 오프라인용으로 자동 저장한다.
- 첫 접속에 전체 게임을 일괄 저장하지 않는다.
- 해당 게임의 필요한 파일이 모두 저장된 경우에만 `오프라인 가능`으로 표시한다.
- 오프라인용 저장에 실패해도 온라인 플레이는 제공한다.
- 오프라인에서 미저장 게임을 선택하면 인터넷 연결이 필요하다고 안내한다.

### 4.3 앱 업데이트

- 새 버전이 있어도 플레이 중인 게임은 현재 버전으로 유지한다.
- 홈으로 돌아왔을 때 업데이트 안내를 표시한다.
- 진행 상태를 저장한 뒤 사용자가 업데이트 버튼을 누르면 새 버전을 적용한다.

## 5. 콘텐츠 — 확정

### 5.1 주제와 스타일

초기 주제는 동물, 우주, 공주, 동화, 교통, 일상이다.
그림 스타일은 윤곽이 선명하고 색이 또렷한 동화책 일러스트로 통일한다.
차이의 크기와 세부 묘사는 난이도에 맞춰 조절한다.

| 난이도 | 차이 개수 | 구성 방향                          |
| ------ | --------: | ---------------------------------- |
| 쉬움   |       7개 | 큰 차이, 적은 세부 묘사            |
| 보통   |       8개 | 중간 크기의 차이, 적당한 세부 묘사 |
| 어려움 |      10개 | 작은 차이도 포함, 풍부한 세부 묘사 |

### 5.2 첫 배포와 이후 운영

첫 배포는 **6개 주제 × 쉬움·보통·어려움 각 1개 = 총 18개 게임**이다.
출시 후에는 주아의 반응을 보고 필요할 때 생성·검수해 추가 배포한다.
정기적인 콘텐츠 추가 일정은 두지 않는다.

## 6. 생성과 품질 확인

### 6.1 프로젝트 전용 Codex 스킬

이미지는 부모의 Mac에서 기존 구독을 활용해 Codex의 이미지 생성 기능으로 제작한다.
프로젝트 전용 스킬을 만들고 부모가 Codex에서 직접 실행한다.

| 입력      | 규칙                                              |
| --------- | ------------------------------------------------- |
| 주제      | 기본 입력                                         |
| 난이도    | 기본 입력                                         |
| 생성 개수 | 기본 입력                                         |
| 장면 설명 | 선택 사항. 생략하면 Codex가 서로 다른 장면을 구성 |
| 일괄 요청 | 주제와 난이도별 생성 개수를 지정하는 요청 지원    |

단일 생성과 일괄 생성을 모두 지원한다.
예시 요청은 `동물 / 보통 / 3개`, `6개 주제 / 각 난이도 / 1개씩`이다.

### 6.2 제작 순서

1. 원본 그림을 생성한다.
2. 난이도에 맞는 차이 7·8·10개를 계획한다.
3. 원본을 편집해 변경 그림을 만든다.
4. 실제 그림의 차이와 정답 영역을 검수한다.
5. 의도하지 않은 차이가 있으면 수정하거나 재생성한다.

스킬은 정답 영역을 표시한 검수용 이미지도 만든다.
일괄 생성 중 일부 항목이 실패해도 성공한 결과는 보존하고 실패한 항목만 다시 생성한다.
검수에서 문제가 발견된 게임도 개별 재생성하며 다른 게임의 결과물은 유지한다.

### 6.3 등록과 품질 확인 — 사용자 변경

- 별도 부모 검수·승인 절차를 두지 않는다.
- 등록된 이미지와 JSON은 자동 데이터 검사를 통과하면 모두 빌드에 포함한다.
- 제작자가 그림·정답 영역·실제 동작을 확인하는 품질 가이드는 유지한다.
- 확인용 이미지와 제작 자료는 공개 배포에 포함하지 않는다.
- 그림이나 정답 영역이 바뀌면 해당 게임의 진행 버전을 갱신한다. 승인을 다시 받는 단계는 없다.

## 7. 기술·빌드·배포·운영 — 확정

### 7.1 기술 스택

| 역할           | 확정한 구성                                      |
| -------------- | ------------------------------------------------ |
| 화면·게임 상태 | React + TypeScript                               |
| 개발·정적 빌드 | Vite                                             |
| PWA            | vite-plugin-pwa + Workbox, `injectManifest` 방식 |
| 진행 기록·설정 | IndexedDB                                        |
| 오프라인 파일  | Cache Storage                                    |
| 그림·정답 표시 | 이미지 요소 + SVG 오버레이                       |
| 입력 처리      | Pointer Events                                   |
| 콘텐츠 검사    | Node.js 스크립트                                 |
| 직접 배포      | Wrangler CLI                                     |

정확한 패키지 버전과 호환성은 구현 시 확인하고 lockfile로 고정한다.

### 7.2 배포 구조

- 등록된 이미지와 JSON을 웹앱과 함께 정적 배포한다.
- 콘텐츠를 추가·수정하면 웹앱을 재배포한다.
- Cloudflare Workers Static Assets 무료 플랜을 사용한다.
- 첫 버전은 Cloudflare 기본 주소에서 가족에게만 제공한다. 자체 도메인은 추후 필요할 때 검토한다.
- Cloudflare Access로 앱·이미지·정답 JSON과 기본 주소·미리보기 등 모든 배포 접근 경로를 보호한다. 접근 보호를 준비하기 전에 무인증 웹 주소를 열지 않는다.
- 기존 오프라인 기능은 유지한다. 인증 후 기기에 저장한 게임은 서버 연결 없이 플레이할 수 있다. 접근 권한 취소는 이후 서버 요청에 적용되며 저장된 파일을 원격 회수하지 않는다.
- 부모 이메일 허용 목록은 Cloudflare에서 관리하며 공개 산출물에 넣지 않는다. 인증 세션 기간과 PWA 재로그인 흐름은 실제 기기에서 확인한다.
- Mac에서 직접 빌드·배포한다.
- 콘텐츠 등록 → 자동 검사 → 빌드 → 정적 배포 흐름으로 운영한다.

### 7.3 장애 대응

문제가 발견되면 이전 정상 버전으로 되돌린다.
문제를 수정·검수한 뒤 재배포한다.
기기의 진행 기록은 4.1절의 변경 기준에 따라 처리한다.

### 7.4 첫 버전 제외 범위

- 로컬·호스팅 어드민과 어드민 계정 로그인
- 웹서비스에서 이미지 생성 API를 호출하는 자동 생성
- 별도 콘텐츠 조회 API 서버
- Git 연동 자동 배포
- 별도 사용 통계 수집
- 앱 회원가입, 아이 계정, 기기 간 진행 기록 동기화
- 배경음악, 시간 제한, 오답 감점, 다음 게임 자동 이동

## 8. 첫 가족 전용 배포의 완료 기준 — 확정

배포 목표 날짜는 정하지 않는다.
기존 기기 확인은 권장 품질 확인이며 수동 승인 절차가 아니다. 가족 전용 접근 보호는 배포 시 충족해야 하는 운영 조건이다.
지금 문서를 작성한 것으로 이 기준을 통과했다고 간주하지 않는다.

| 기준          | 통과 조건                                                                  | 현재 상태 |
| ------------- | -------------------------------------------------------------------------- | --------- |
| 가족 접근 제한 | 미인증·미허용 이메일의 앱·이미지·정답 JSON 직접 요청 차단. 기본·미리보기 주소 보호 | 미설정·미검증 |
| 부모 인증 | 허용 이메일 로그인, Safari·홈 화면 PWA의 만료 후 재로그인 확인 | 미설정·미검증 |
| 콘텐츠        | 18개 게임 모두 검수용 이미지와 실제 게임 화면의 직접 확인 통과             | 미검증    |
| 실제 기기     | iPad A16의 Safari·홈 화면 PWA에서 정답 선택, 확대·이동, 힌트, 완료 확인    | 미검증    |
| 이어 풀기     | 앱을 닫고 다시 열었을 때 진행 중인 게임과 찾은 정답 복원                   | 미검증    |
| 오프라인      | 열어본 게임 플레이, 미저장 게임 안내, 저장 실패 시 온라인 플레이 확인      | 미검증    |
| 업데이트      | 플레이 유지, 홈 안내, 저장 후 버튼 적용, 변경 종류별 기록 유지·초기화 확인 | 미검증    |
| 주아의 플레이 | 조작이나 정답 판정 때문에 진행하지 못하는 문제 없음                        | 미검증    |

## 9. 구현 권장안 — 제품 요구사항과 구분

이 절의 파일명·수치·내부 구조는 인터뷰에서 확정한 제품 요구사항이 아니다.
구현과 iPad A16 검증을 통해 조정한다.

### 9.1 파일 구조와 스킬 산출물

```text
.agents/skills/generate-game/SKILL.md   # 프로젝트 전용 스킬
work/content/<game-id>/                # 제작 중 결과·차이 계획·실패 기록
work/content/<game-id>/                # 로컬 제작·확인 자료
content/games/<game-id>/               # 빌드 후보 파일
  original.webp
  modified.webp
  thumbnail.webp
  puzzle.json
  metadata.json
scripts/                              # 검증·내보내기·배포 스크립트
src/                                  # 웹앱과 서비스 워커
public/                               # 아이콘 등 공개 가능한 공통 파일
build-content/                        # 등록된 콘텐츠를 내보낸 중간 결과
dist/                                 # 실제 배포 산출물
```

제작 폴더와 검수 기록을 `public/` 아래에 두지 않는다.
빌드는 허용 목록으로 공개 파일만 내보낸다. 제외 패턴만으로 공개 범위를 결정하지 않는다.
검수는 실제 배포할 포맷으로 변환한 이미지에서 수행한다.
초기 포맷은 WebP를 권장하되 압축 후 작은 차이가 사라지지 않는지 확인한다.
원본 보관 파일과 검수용 이미지는 별도 로컬 폴더에 보존한다.

### 9.2 콘텐츠와 진행 기록의 식별

| 값                 | 역할                                                          |
| ------------------ | ------------------------------------------------------------- |
| `gameId`           | 제목이 바뀌어도 유지하는 게임 고유 ID                         |
| `gameplayRevision` | 공개 그림 쌍과 정답 영역의 의미 있는 내용으로 계산하는 식별값 |
| `metadataRevision` | 제목·주제·난이도·썸네일 등 표시 정보의 식별값                 |
| `releaseId`        | 웹앱과 게임 목록을 함께 식별하는 배포별 값                    |
| `schemaVersion`    | JSON과 저장 데이터의 형식 버전                                |

진행 기록은 `gameId`와 `gameplayRevision`에 연결한다.
제목·썸네일 변경은 `metadataRevision`만 바꿔 진행 기록을 유지한다.
정답 JSON의 공백이나 키 순서만 바뀐 경우에는 재검수하되 실제 게임 버전은 불필요하게 바꾸지 않는다.
게임 버전은 증가 숫자의 대소보다 현재 그림·정답 내용의 일치 여부로 판단한다. 이전 배포로 복구할 때도 같은 원칙을 적용한다.

`puzzle.json`에는 이미지 크기, 좌우 이미지 경로, 차이별 ID와 좌우 판정 영역을 둔다.
`metadata.json`에는 제목·주제·난이도·썸네일을 둔다.
양쪽의 같은 차이는 같은 ID를 사용한다. 어느 쪽에서 맞혀도 한 번만 정답으로 센다.
영역 좌표는 이미지 기준 0~1로 정규화하고, 첫 구현은 타원 영역을 권장한다.
양쪽 판정 영역은 따로 정의할 수 있게 해 이동·삭제 차이도 표현한다.
힌트는 판정 영역보다 넓은 주변을 강조해 정확한 터치 위치를 바로 드러내지 않는다.

### 9.3 자동 데이터·빌드 검사

게임별 승인 기록과 실제 기기 확인 플래그를 빌드·배포 조건으로 요구하지 않는다. 아래 자동 검사는 유지한다.

- 주제·난이도·JSON 형식, 게임 ID와 차이 ID 중복
- 쉬움 7개·보통 8개·어려움 10개의 정답 수
- 이미지 쌍의 크기, 좌표 범위, 필수 파일 존재
- 등록 목록과 빌드 목록 일치, 파일 해시와 산출물 일치
- 제작 자료와 비공개 파일의 산출물 포함 여부
- 첫 공개의 6개 주제 × 3개 난이도 기본 구성
- 파일 크기와 서비스 워커 사전 캐시 목록

모든 등록 게임을 포함한다. 빌드 후 파일·목록이 바뀌면 다시 빌드한다. 실제 기기 확인은 권장 품질 확인이며 수동 승인 단계가 아니다.

### 9.4 터치·확대·화면 회전

한 손가락이나 Pencil의 짧은 탭은 정답 선택에 사용한다.
두 손가락은 확대·이동에 사용한다. 여러 손가락이 참여한 제스처 끝을 정답 탭으로 처리하지 않는다.
Pencil 접촉 중 손바닥 접촉으로 화면이 움직이거나 오답이 발생하지 않는지 실제 기기에서 확인한다.
터치 좌표는 그림 여백·확대·이동을 역변환해 정답 영역과 비교한다.
두 그림은 하나의 확대·이동 상태를 공유한다.
회전 시 찾은 정답을 유지하고 확대·이동을 기본 상태로 재배치한다.
이미 찾은 정답을 다시 눌러도 정답 수·효과음·진행 기록을 중복 처리하지 않는다.
작은 차이의 터치 여유는 화면 기준으로 조절하되 인접 정답 영역과 혼동하지 않도록 검수한다.

### 9.5 피드백의 초기 권장값

| 항목                  | 초기 권장값                                         |
| --------------------- | --------------------------------------------------- |
| 힌트 강조             | 약 2초                                              |
| 오답 표시             | 약 0.5초                                            |
| 완료 애니메이션       | 약 1~1.5초                                          |
| 최초 소리 설정        | 꺼짐. 사용자가 켠 뒤 기기에 저장                    |
| 전체 진행 기록 초기화 | 진행 기록만 삭제하고 소리 설정·오프라인 파일은 유지 |

힌트가 확대 화면 밖에 있으면 해당 주변을 볼 수 있도록 두 그림의 보기 위치를 함께 조정한다.
필터 선택과 확대 상태는 정답 기록과 분리한다. 필터·확대 상태의 재실행 복원은 필수 공개 조건에 추가하지 않는다.
축하 애니메이션은 입력을 오래 막지 않고, 동작 줄이기 설정에서는 짧은 표시로 대체한다.

### 9.6 오프라인 파일과 저장 실패

앱 기본 파일, 현재 게임 목록, 썸네일과 실제 게임 파일의 캐시를 구분한다.
홈의 썸네일을 본 것만으로 해당 게임이 오프라인 저장됐다고 처리하지 않는다.
게임을 열면 그 버전의 그림 쌍과 정답 JSON을 저장하고, 필수 파일 전체를 확인한 뒤 완료 표시를 기록한다.
부분 저장은 오프라인 가능으로 표시하지 않으며 재시도할 수 있게 한다.
조회 시 실제 캐시 존재 여부도 확인해 브라우저가 파일을 삭제했을 때 표시가 남지 않도록 한다.
저장 실패 시 플레이를 막지 않고 다음 온라인 게임 진입 때 다시 시도한다.
첫 구현은 사용자가 선택하지 않은 게임 파일의 자동 용량 삭제를 피하고 수동 삭제를 우선한다.
캐시 용량 상한은 초기 게임의 실제 파일 크기를 측정한 뒤 정한다.

IndexedDB 쓰기는 정답 확정 때 수행한다. 업데이트·화면 종료에만 저장을 의존하지 않는다.
저장 실패를 인지하면 재실행 후 복원이 보장되지 않는다는 짧은 안내를 제공한다.
기기 저장은 브라우저 정책·사용자의 데이터 삭제로 사라질 수 있다. 영구 보관을 보장하지 않는다.

### 9.7 업데이트와 복구

앱 기본 파일만 사전 캐시하고 게임은 열었을 때 저장한다.
그림과 정답 JSON의 URL에 게임 버전을 포함해 서로 다른 버전을 섞지 않는다.
게임 시작 때 그 버전의 필수 파일을 확보하고 현재 게임은 같은 버전으로 끝까지 유지한다.

새 서비스 워커는 대기 상태로 두고 홈에서만 업데이트 안내를 표시한다.
진행 기록 저장이 성공한 뒤 버튼으로 새 버전을 활성화한다.
저장·업데이트에 실패하면 현재 정상 버전을 유지하고 홈에서 다시 시도할 수 있게 한다.
업데이트 과정에서 진행 기록 저장소를 삭제하지 않는다.
오래된 캐시는 새 버전의 실행과 사용 중인 게임의 안전을 확인한 뒤 정리한다.

서버 배포 복구와 기기에 저장된 PWA 복구는 별도 단계로 확인한다.
이전 정상 배포로 되돌린 뒤 현재 기기가 그 버전을 감지하고 적용하는지 검증한다.
필요하면 이전 정상 코드·콘텐츠에 새 `releaseId`를 부여해 복구 배포를 만들고 같은 업데이트 흐름으로 적용한다.
전체 브라우저 데이터 삭제를 일반 복구 절차로 사용하지 않는다.

### 9.8 개발·검사·배포 명령과 운영 기록

| 제안 명령         | 역할                                          |
| ----------------- | --------------------------------------------- |
| `npm run dev`     | 웹앱 로컬 실행                                |
| `npm run check`   | 타입·정답 데이터 검사                         |
| `npm run build`   | 등록 콘텐츠 내보내기와 정적 빌드              |
| `npm run preview` | 실제 빌드 결과의 로컬 확인                    |
| `npm run deploy`  | 검사·빌드·산출물 확인 후 Wrangler로 직접 배포 |

위 명령은 아직 존재하지 않는다. 구현 시 스크립트를 작성하고 검사 실패 시 배포가 중단되도록 연결한다.
배포 인증은 Mac의 Wrangler 로그인으로 관리하고 인증 정보를 저장소·공개 산출물에 넣지 않는다.
배포마다 `releaseId`, 코드 버전, 게임 버전 목록, 검증 결과, 복구 대상의 배포 ID를 로컬에 기록한다.
제작 원본·성공한 생성 결과·검수 기록은 공개 파일과 분리해 로컬 백업한다.
초기 18개 검증은 로컬 빌드와 실제 기기 검증으로 진행한다. 서비스 워커 검증에는 로컬 HTTPS 등 보안 컨텍스트를 확보한다. 공개 미리보기 URL을 검수 전 배포 경로로 사용하지 않는다.

### 9.9 구현과 검증의 권장 순서

1. 게임 1개로 원본 생성·편집·품질 확인 파일 흐름을 검증한다.
2. 홈·플레이·힌트·확대·진행 저장을 구현하고 iPad A16에서 확인한다.
3. 오프라인 저장·사용자 선택 업데이트·복구를 검증한다.
4. 일괄 생성과 실패 항목 재생성을 검증하고 초기 18개 게임을 준비한다.
5. 공개 산출물 검사와 8절의 기준을 모두 통과한 뒤 첫 공개 배포를 수행한다.

정답 판정·버전 비교·산출물 해시 검사는 자동 검증한다.
입력·배치·PWA 동작은 브라우저 검증과 실제 iPad A16 검증으로 확인한다.
주아의 사용성 확인은 자동 테스트로 대체하지 않는다.

## 10. 구현 시 확인할 사항

제품 범위에 대한 열린 질문은 없다. 아래 항목은 구현 중 확인하고 결과를 기록한다.

- 패키지·Node.js·Wrangler 버전의 호환성과 lockfile
- iPad A16의 실제 iPadOS 버전, 사용 가능한 Apple Pencil, 손가락·펜 입력 결과
- 실제 생성 도구의 이용 가능 여부와 구독 사용 한도. 생성 실패를 이유로 별도 과금 API로 자동 전환하지 않는다.
- 작은 차이를 보존하는 이미지 해상도·압축률·용량과 첫 게임 로딩 시간
- 정답 영역과 터치 여유, 힌트 표시 시간, 소리 기본값에 대한 실제 플레이 결과
- 생성 실패 재시도 상한. 초기에는 실패 기록을 남기고 명시한 항목을 다시 실행하며 무제한 자동 반복을 피한다.
- IndexedDB·Cache Storage 저장 실패, 저장 공간 삭제, 업데이트 실패와 복구 배포 감지
- 등록된 콘텐츠와 일치하는 산출물만 공개되는지와 첫 배포의 18개 콘텐츠 조건

## 12. 숨은그림찾기 확장 — 2026-10-29 사용자 승인

사용자가 화면 시안 3장을 승인하고 구현과 숨은그림 콘텐츠 30개 제작을 요청했다. 기존 틀린그림찾기와 진행 기록을 보존한다. 앱 진입은 놀이 선택 → 놀이별 목록 → 플레이 순서로 바뀐다. 기존 게임 직접 링크는 계속 해당 게임을 연다.

숨은그림찾기는 장면 한 장의 사물 윤곽·무늬에 섞인 물건을 찾는다. 목표 목록은 작은 그림과 이름을 함께 제공한다. 가로에서는 오른쪽, 세로에서는 본그림 아래에 둔다. 목표를 미리 선택하지 않아도 장면을 바로 눌러 찾을 수 있다. 찾은 항목은 원래 위치에서 체크와 함께 유지한다. 모든 목표를 찾으면 직접 다른 그림 또는 다시 풀기를 고른다.

시간 제한·감점 없음, 정답·오답·완료 효과음, 무제한 주변 힌트, 확대·이동, 이어 풀기, 현재 게임만 다시 풀기는 두 놀이에 공통으로 적용한다. 소리 설정은 공유한다. 전체 진행 기록 초기화 확인에는 두 놀이가 포함된다고 명시한다. 오프라인은 장면·정답·목표 그림·썸네일 전체를 저장했을 때만 가능으로 표시한다.

콘텐츠는 기존 6개 주제에 5개씩 추가한다. 쉬움 7개·보통 8개·어려움 10개의 목표를 갖는 콘텐츠를 각각 10개 제작한다. 제작은 서브에이전트에 나누어 맡긴다. 최종 장면·목표 추출·판정 영역의 시각 확인과 데이터 검사는 유지한다. 실제 iPad·주아의 체감 난이도 검증은 별도다. 공개 배포는 이번 요청에 포함되지 않는다.

### 12.1 숨김과 목표 그림 교정

사용자는 첫 제작 결과가 전체적으로 쉽고 목표 그림에 배경이 노출되며 숨긴 물건이 주변 그림과 다르다고 지적했다. 숨은그림은 첨부 책처럼 평면적인 색면과 일정한 잉크 윤곽으로 제작한다. 숨긴 모양에도 같은 색·선·명암을 쓰고 장면의 사물 경계·주름·무늬를 공유한다. 목표 그림은 주변 배경 없는 투명 PNG이며, 위치·재질 단서를 주지 않는 중성색의 간단한 윤곽을 우선한다. 단순히 대상을 작고 흐리게 만들어 난이도를 높이지 않는다.
