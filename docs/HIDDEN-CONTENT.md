# 숨은그림찾기 콘텐츠 계약

2026-10-29 사용자 승인: 시안대로 구현하고 서브에이전트로 숨은그림 30개 제작. 기존 틀린그림찾기는 보존한다. 공개 배포는 요청하지 않았다.

## 파일과 데이터

게임별 `content/games/hidden-<theme>-<difficulty>-<scene>/`에 완성본을 둔다. 기존 게임 ID와 겹치지 않는다. 제작 자료는 `work/hidden-content/<id>/`에 보존한다. metadata.json:

```json
{"schemaVersion":1,"kind":"hidden","id":"hidden-animals-easy-garden","title":"토끼의 작은 정원","theme":"동물","difficulty":"easy","thumbnail":"thumbnail.webp"}
```

puzzle.json:

```json
{"schemaVersion":1,"kind":"hidden","id":"hidden-animals-easy-garden","width":1536,"height":1152,"original":"scene.webp","targets":[{"id":"target-1","label":"나뭇잎","image":"target-01.png","area":{"x":0.2,"y":0.3,"rx":0.045,"ry":0.06}}]}
```

정답은 easy 7개·medium 8개·hard 10개다. width/height는 최종 장면 파일의 실제 크기다. original, thumbnail, 모든 target image는 서로 다른 안전한 파일명이다. 모든 area는 0~1 정규화 타원이며 이미지 안에 온전히 들어간다. 각 정답의 id는 고유하다. 목표 이미지는 최소 96px, 보통 160~240px의 투명 PNG다. 장면의 실제 숨긴 모양에 대응하는 물건 자체만 보여준다. 주변 배경·상황·위치 단서를 포함한 사각 crop은 금지한다. 내장 image_gen으로 장면을 참조해 투명 cutout 시트를 만들고 타일을 분리할 수 있다. 장면과 별개로 만든 닮은 그림을 원본과 같다고 취급하지 않는다. 최종 윤곽·비율·세부 대응을 눈으로 검수한다.

장면은 단일 동화책 그림, 가로 4:3을 요청한다. 실제 생성 비율은 존중하며 자르지 않는다. sharp로 포맷·크기 변환과 투명 시트 타일 분리·썸네일 제작만 허용한다. 배경 제거와 물건의 의미를 바꾸는 편집은 내장 image_gen으로 수행한다. 코드로 장면이나 물건을 그리거나 붙이지 않는다. 썸네일은 원본 비율을 유지한 폭 600px이다. scene.webp는 시각 세부를 보존하도록 높은 품질로 저장한다. 원본 생성 PNG와 실제 프롬프트를 제작 폴더에 보존한다.

## 제작 품질

이미지 생성은 내장 image_gen만 사용한다. 각 게임마다 생성 전 plan.json에 제목·장면·7/8/10개의 숨길 모양과 위치를 구체적으로 기록한다. 나무결·구름·꽃무늬·천 주름·물결·바위 윤곽 등에 물건의 모양을 자연스럽게 섞는다. 장면에 독립된 물건을 작게 놓는 방식만으로 구성하지 않는다. 쉬움은 몇 개의 쉬운 대상을 섞되, 어려움은 작은 판정 범위가 아닌 관찰할 맥락과 모양으로 조절한다. 비슷한 대상 반복과 모든 게임에서 같은 물건 목록 사용을 피한다.

결과를 view_image로 직접 보고 계획한 숨은 모양이 각각 실제 존재하는지 확인한다. 정답마다 명확한 윤곽을 확인하고 최종 위치를 기록한다. 계획과 다른 우연한 물건으로 정답 수를 채우지 않는다. 누락·겹침·불명확한 윤곽이면 이미지 도구로 해당 장면을 수정한다. 재시도 최대 한 번이며 계속 실패하면 실패를 기록하고 다음 게임을 진행한 뒤 담당자에게 알린다. 품질 낮은 콘텐츠를 성공으로 등록하지 않는다.

최종 scene·목표 추출 이미지·정답 표시 검수 이미지를 각각 확인한다. target crop은 의미를 바꾸지 않는 추출이다. `review.png`(scene 위 정답 타원과 번호)와 목표 contact sheet는 제작 폴더에만 둔다. 자동 데이터 검사는 시각 검수를 대신하지 않는다. review.json에는 확인한 대상·실제 좌표·문제와 수정 이력·미확인 사항을 기록한다. iPad 실기기·주아 난이도는 확인하지 않았다고 쓴다.

## 동시 작업

제작 에이전트는 자기 할당 ID의 content/games와 work/hidden-content 폴더만 수정한다. src·scripts·공유 문서·다른 게임을 변경하지 않는다. export/build/stage 명령은 공유 산출물을 덮어쓰므로 실행하지 않는다. 완료한 파일은 원자적으로 등록하고 결과를 루트 에이전트에 보고한다. 30개 목록은 work/hidden-content/batch-30.json을 따른다.


## 2026-10-29 사용자 난이도 교정 — v2 우선

사용자는 ‘전반적으로 너무 쉬움’, ‘찾을 물건에 배경이 포함되어 위치를 쉽게 알 수 있음’, ‘숨긴 물건이 그림과 너무 티나게 다름’을 지적했다. 기존 성공 파일은 보존하되 이 지적을 통과한 것으로 취급하지 않는다. 담당별 한 장을 먼저 개선하고 루트가 장면과 투명 목표를 검토한 뒤 전체 30개에 적용한다.

- 목표는 물건 자체만 표시한다. 주변 배경 없는 실제 알파 투명도를 검사한다.
- 장면에서는 대상이 독립된 기호·각인·양각·스티커·색상 패치로 튀지 않아야 한다. 같은 색·선·명암·재질을 써서 기존 사물의 윤곽·주름·가지·물결·음영 경계가 그 모양을 만들게 한다.
- 단순히 크기를 작게 하거나 흐리게 해서 어렵게 만들지 않는다. 기본 화면에서 관찰할 수 있는 크기를 유지한다.
- 기존 content 완성본·생성 PNG·검수 자료는 work/hidden-content/<id>/v1-archive에 보존한다. 수정한 게임만 진행 버전이 바뀐다. 기존 틀린그림찾기 기록에는 영향을 주지 않는다.

### 위장과 일반 사물 찾기의 구분

이번 요청은 사진 같은 숨은그림찾기다. 실제 잎을 ‘나뭇잎’, 실제 리본을 ‘리본’, 실제 곰 발을 ‘발바닥’으로 부르는 항목만 모으면 단순 사물 찾기가 되므로 개선 완료로 보지 않는다. 목표와 host가 서로 다른 조합을 사용한다. 예를 들어 물고기 모양을 돌 윤곽이나 천 무늬 속에, 숟가락 모양을 귀 안쪽 윤곽에 섞는다. 같은 잉크·현지색의 완결된 패턴도 허용하지만 대상이 큰 배지·고대비 기호로 튀어서는 안 된다.

제작 기준으로 쉬움은 최소5/7, 보통7/8, 어려움10/10을 다른 사물·무늬 속 모양으로 구성한다. 동일 종류가 장면 여러 곳에 있으면 목표 그림의 고유한 윤곽으로 구분할 수 있어야 한다. 우연히 발견한 일반 사물에 사후 이름을 붙여 개수를 채우지 않는다. plan과 review에 target-host 조합과 실제 대응을 남긴다.

## 기존 앱과 카탈로그 호환

`catalog.json`은 schemaVersion1을 유지한다. `games`에는 기존 틀린그림찾기만, `hiddenGames`에는 새 숨은그림찾기를 넣는다. 새 앱은 두 배열을 합쳐 놀이별로 보여준다. 이전 앱은 알 수 없는 숨은그림 형식을 잘못 열지 않고 기존30개를 계속 이용할 수 있다. 산출물 검사는 두 배열의 합계·종류·각 항목의 메타데이터와 URL을 원본과 대조한다.

## 물건 이름·형태·목표 카드의 대응 — 2026-10-29 교정

전등갓을 종으로, 네 갈래 리본 끈을 나비로, 구멍 난 뒤집개를 포크로 인정했던 검수 기준을 교정한다. 단순히 비슷한 외곽이 있다는 이유로 물건의 이름을 붙이지 않는다. [형태 개선 결과](verification/hidden-shape-fix-20261029.md)에 19개 게임·35개 목표의 처리 근거를 남겼다.

- 이름을 판단할 핵심 구조를 확인한다. 종은 몸통·벌어진 입구·종추가, 나비는 몸통·네 날개·더듬이가 읽혀야 한다. 포크는 살 사이가 끝까지 열려 있어야 한다. 양쪽 끝이 모두 뜨는 부분인 모양을 일반 숟가락으로 취급하지 않는다.
- 카드는 최종 장면의 실제 윤곽에서 제작한다. 일반적인 물건 그림으로 바꾸거나 장면에 없는 꼬리·날개·리본 끈을 추가하지 않는다. 방향·비율·주요 부품 수·끝 모양을 나란히 비교한다.
- 이름만 실제 전등·리본으로 바꾸는 수정은 숨긴 모양 찾기의 개선으로 보지 않는다. 필요한 경우 원래 이름의 물건을 다른 사물의 무늬 안에 다시 계획하고 장면과 카드를 함께 고친다.
- 장면을 편집하면 같은 게임의 모든 목표를 다시 확인한다. 실제 위치가 바뀌거나 정답 크기가 달라졌으면 판정 영역도 조정하고 기본 화면·확대 화면의 선택을 확인한다.
- 투명 PNG는 알파 값 검사와 함께 흰 배경·실제 카드 배경에 합성해 검수한다. 알파가 0인 픽셀의 RGB 값이나 특정 미리보기의 표현만으로 배경이 있다고 판정하지 않는다. 검수용 합성본은 게임 카드로 등록하지 않는다.
